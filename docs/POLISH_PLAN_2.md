# 墨枢 · 第二轮 30 轮精细打磨计划（R51–R80）

对标对象：Day One（记忆重现、模板、导出）、Bear（标签体系、Markdown）、Flomo（快速记录、热力图）、
Obsidian（双向链接、反链）。审计方式是先按功能面 grep 现有代码，只写确实缺失的轮次。

约定与前 50 轮相同：不写入任何 API Key；默认模型用稳定别名 `deepseek-flash`；
改实体必须升 `AppDatabase.version` 并补 `MIGRATION_n_m`；每个批次跑 `assembleDebug testDebugUnitTest`。

## 一、记录与组织

- **R51 标签管理**：`tagsJson` 目前只能由 AI 写入，用户无法重命名/合并/删除标签。新增「标签」管理页：
  列出全部标签及条目数，支持重命名、合并到另一标签、删除（仅从条目上摘掉，不删条目）。
- **R52 往年今日**：「今天」页新增「往年今日」卡片，展示去年/前年同一天（±1 天）的记录；无内容时不显示。
- **R53 回收站**：删除目前直接消失。新增软删除（`EntryEntity.deletedAt`）与回收站页，
  保留 30 天，支持恢复与彻底删除；列表与搜索默认排除已删除项。
- **R54 星标条目**：`isPinned` 是「置顶」，缺少「收藏但不置顶」。新增 `isStarred` 与筛选，详情页可切换。
- **R55 模板**：新增记录模板（晨间日记 / 复盘 / 读书笔记 / 空白），在输入框上方可选，
  模板内容预填进草稿，模板存本地设置。
- **R56 双向链接**：正文里写 `[[标题]]` 时渲染成可点链接，跳转到同名条目；
  详情页底部显示「被引用」反链列表。解析在内存完成，不改表结构。

## 二、阅读与检索

- **R57 正文可调字号**：详情页正文支持字号三档（小/标准/大），设置持久化，长文阅读更舒适。
- **R58 条目内搜索并定位**：详情页支持搜索当前正文，命中处高亮并逐条跳转。
- **R59 详情页左右滑动切换**：在当前筛选结果内左右滑动切到上一条/下一条，避免反复返回列表。
- **R60 最近搜索词**：搜索框聚焦时展示最近 8 条搜索词，可单条删除或全部清空。
- **R61 全库日历视图**：月历标出有记录的日子（按条数深浅着色），点击某天跳到当天记录。
- **R62 全年热力图**：回顾页把「本月热力图」扩展为「近一年」，点击格子跳到对应月份。

## 三、统计与洞察

- **R63 写作统计**：新增写作统计卡：累计字数、平均每条字数、最长连续天数、最常写的时间段。
- **R64 情绪与标签关联**：回顾页显示「最常与某情绪共现的标签」，帮助发现自己的模式。
- **R65 字数与阅读时长**：详情页显示本条字数；列表卡片可选显示字数。

## 四、导出与分享

- **R66 导出单条为 Markdown 文件**：详情页可把当前条导出成 `.md` 文件（`ACTION_CREATE_DOCUMENT`）。
- **R67 批量导出为 Markdown**：记忆页多选后导出所选条目为一个 Markdown 文件。
- **R68 导出带图片**：导出 Markdown 时可选打包图片（zip），图片按条目分目录。

## 五、可靠性与隐私

- **R69 应用锁**：支持 PIN 或生物识别解锁，开启后进入应用需验证；密钥与设置不进备份。
- **R70 自动备份**：按天/周自动导出备份到指定目录（SAF 持久授权），失败有通知。
- **R71 提醒通知的直接操作**：待办提醒通知增加「完成」与「推迟一天」按钮，不必进应用。
- **R72 桌面快捷方式**：长按图标可「写一条」「搜一搜」「看往年今日」。
- **R73 数据完整性自检**：启动时检查孤儿附件、无效分类、悬空待办来源，并在设置页提供一键修复。

## 六、打磨

- **R74 图片查看器手势**：大图支持双指缩放与拖动，双击放大/还原。
- **R75 深色跟随时间**：外观增加「日出日落自动切换」（按本地时间粗略计算）。
- **R76 空状态与引导**：各页空状态给出下一步动作按钮，而不是只有一句说明。
- **R77 无障碍完善**：补齐卡片、图表、图标的 TalkBack 描述与状态播报。
- **R78 性能：列表与图片**：记忆页长列表的图片解码与滚动优化，避免掉帧。
- **R79 键盘与外接设备**：外接键盘支持 Ctrl+F 搜索、Ctrl+N 新建、Esc 返回。
- **R80 收尾清理**：重复实现合并、无引用符号删除、文案一致性复查。

# 第三轮：日历、自定义事件与自然语言安排

## 一、日历与「当天的安排」

- **新增 `events` 表**（schema v6 + `MIGRATION_5_6`）：标题、备注、发生时刻、全天、重复规则、
  提前量、**独立铃声**、重要级别、完成态。
  与 `todos` 分开建表：待办只有截止日、按天粒度；事件要精确到分钟、要重复规则、
  要各自铃声与重要级别——塞进一张表会让两边都变成一堆可空字段。
- **日历页**（底部导航第 5 项）：月网格（周一起始，符合中文习惯）、有安排的日子打点、
  点某天看当天安排。同一天还并列显示**当天的记录**，便于「计划 vs 实际」对照。
- 「今天」页新增「今天的安排」，时间敏感的事排在记忆之前。

## 二、每个事件自选提醒铃声

Android 的硬约束：**通知渠道的声音在创建后不可修改**。因此按「铃声 + 重要级」建渠道，
而不是一个事件一个渠道——后者会让渠道列表随事件数无限膨胀，而铃声种类通常只有个位数。

真机验证（`dumpsys notification`）：

```
mId='journal_event_default_b8b19b31'  mSound=...media/180?title=Aldebaran
mId='journal_event_default_f7781a10'  mSound=...media/138?title=Antares
```

两个事件、两种铃声、两条渠道，各自绑定真实音频 URI。

- 铃声选择器给出系统铃声列表 + 静音 + 系统默认，**每一项都能试听**
  （铃声名字看不出听感，「Chime」和「Tiptoe」差别很大）。
- 渠道在**保存时**就建好，而不是等提醒响了才建：提前建出来用户能在系统设置里看到并调整，
  铃声 URI 有问题也在保存那一刻暴露。

## 三、提醒调度

- 用 `AlarmManager` 而非 WorkManager：事件是「14:30 的会」这类到点必须响的提醒，
  WorkManager 在 Doze 下的延迟可达十几分钟，会让提醒失去意义。
- Android 12+ 精确闹钟需 `SCHEDULE_EXACT_ALARM`。**未授权时不静默失准**：
  退回窗口闹钟，并在日历页显示警告 + 「去授权」直接跳到系统设置。
- 重复规则按日历单位推进而非加固定毫秒数，并夹到当月最后一天
  （1 月 31 日的「每月」在 2 月落到 28/29 日，而不是跑到 3 月）。
- 设备休眠导致迟发时，通知里如实写明「延迟 N 分钟送达」。
- 开机 / 改时区 / 改系统时间后重排（`BootReceiver` 已扩展）。

## 四、自然语言安排（「说一句，我来安排」）

用户例子：「这周五八点记得去上实验课」→ 自动排到**当周周五 07:00 提醒**（事件 08:00）。

分工：
- **本地确定性解析器**（`EventIntentParser`）先跑：今天/明天/后天/这周五/下周一/N月N日/
  N天后/每天/每周/上午八点/晚上八点/提前半小时… 全部支持。离线可用、瞬时出结果、
  且可单测覆盖——日期算错是这类功能最致命的缺陷，AI 每次答案可能不同，测不稳。
- **AI 兜底**（`AiEventPlanner`）：本地读不出日期时才调用已配置的 BYOK 服务。
  模型返回的日期**再校验一遍**（过去太久的直接拒绝），并让它给结构化字段、
  由本地换算成绝对时间——让语言模型做日期算术是已知的不可靠来源。
- **一律先确认再落库**：把「下周五」听成「本周五」比不安排更糟。确认卡片显示
  「读到了什么」和「从哪句话读出来的」，解析不准可一键「改一下」带进完整编辑器。

顺带把分享入口做了分流：分享的句子**自带日期就跳到日历**并解析，否则按原逻辑进「今天」写记录。

真机实测：

```
输入（分享）：这周五八点记得去上实验课
确认卡片：  去上实验课
            9月25日 星期五 · 08:00 · 提前 1 小时提醒
            本地解析 · 日期来自「这周五」 · 时间来自「8点」
确认后：    已安排「去上实验课」，将在 9月25日 07:00 提醒
```

## 七、过程中修掉的自身缺陷

- **一次性事件排不上提醒**：`nextTriggerAt` 拿 `RepeatRule.nextAfter` 当基准，
  而它对「不重复」直接返回 null，导致所有一次性事件都没有提醒。单测抓到。
- **中文数字正则贪婪吞字**：「这周五八点」里匹配到「五八」，整段转换失败，
  时间解析不出。改为从最长开始试、失败退到更短尾部。
- **「分」前的中文数字没转换**：「九点四十五分」只读到 9 点整。
- **选项溢出**：「重复」5 个档位与提醒 6 个档位在窄屏被裁掉（「每年」不可见），改用 FlowRow。
- **分享文本被「今天」页抢走**：它是起始目的地，会立刻消费草稿，日历页永远拿到空串。
  改为按分流结果显式归属。
